# TPL功能描述

我想做一个基于Web的测试计划与执行记录工具。

## 要求

- 基于Web技术，后端使用 Python(FastAPI) + PostgreSQL，前端使用 TypeScript(Svelte)
- 前端应用可以与后端交互，将数据存储于后端；也可以离线使用，通过导入、导出JSON完成数据交换
- 包含多个模块

    - Building blocks定义（风险blocks、测试方案blocks）
    - 项目创建
    - 测试过程创建（planning）
    - 测试执行记录（logging）

- 每种资源有自己的独立ID，可以被分享、修改

## 目标

新产品设计可能出现哪些风险，这些风险需要通过什么测试方案来覆盖。
这些内容可以作为模板被后续引用，简单地参数修改即可。

当定义一个项目的时候，包含哪些风险，采取哪些方案，哪些风险在以前的项目中已经被验证过了（虽然不需要做测试、但是还是得体现在项目定义中）。
如此可以知道覆盖率是多少，每个步骤结束之后，风险覆盖率的变化情况。

根据测试方案，需要定义测试步骤，测试方案能够提供一些基础的模板步骤，具体细节则需要详细定制。

实际执行测试的时候，每个步骤需要做什么、执行输入参数是什么、步骤合格的条件是哪些等等，这些内容需要将起止时间记录。

## 模块详细

### blocks定义

风险blocks说明哪些部件会有怎样的潜在风险，标题、描述、出现范围。

测试方案blocks也有一个个block组成，每个方案标题、描述、测试方法、能够覆盖的风险。
需要怎样的设备、传感器，以及其推荐的测试步骤。

### 项目创建

项目创建时，可以将风险加入其中，随之自动推荐对应的测试方案。
也可以在风险方案中，输入以前的测试项目将其覆盖。

### planning

测试计划由项目的推荐步骤初始化。
可以自由添加、编辑、删除步骤，也可以自由分组，创建组中组。

步骤有定义执行输入参数、运行时长、过程中需要采集哪些信息、步骤完成标准。
还有预计时长（包含换型过程），这样可以生成计划甘特图。

### logging

logging模块基于planning模块创建，能够显示已完成了哪些步骤、正在进行的、以及未执行的。

记录模块要能灵活的添加新的记录，以便突发情况、临时步骤能够被正确的记录。

主界面显示当前正在执行的步骤，提示该步骤需要的输入参数，进入下一步需要满足的条件，如果各个条件满足，则可进入下一步，点击的同时记录好时间并自动开启新的步骤。
主界面还要有紧急事件按钮，突发情况时按下并开始计时，等待用户输入原因或者归类到正确的步骤。

对于同一个步骤，可以进行多次的记录，当点击步骤时，能显示出所有相关的时间记录。

有的步骤是有多次执行要求的，每次完成，次数+1。

最终根据实际测试的时间记录，能够生成甘特图知道做了哪些测试，也可以进行数据统计（哪些步骤占了多少时间比例）。

记录模块可能会离线使用，此时信息保存在本地，可以导出、导入，等到连上服务后可以将离线内容上传更新。

logging主页显示正在进行的任务，可以点击进入详情页进行记录。
